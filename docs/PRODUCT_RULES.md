# StockBoda Product Rules

담당: 유지해야 할 사용자 동작과 제품 의도.
근거: [서버 권한 정책](../backend/core/access_control.py), [AI 실행](../backend/core/ai_review_v2.py), [매매 화면](../frontend/src/components/TradingJournal.jsx), [광고 정책](../frontend/src/mobile/admobPolicy.js).
기존 정책 문서에서 재사용한 의도는 아래와 같다. 실제 Play Console 가격·이벤트 시작일·운영 설정은 미검증이다.

## 사용자 경험의 불변조건

- 일반 복기(basic)와 심화 복기(advanced)는 분석 종류이며 Pro는 구독이다. 사용자에게 모델명으로 새로운 등급을 만들지 않는다.
- 선택한 매매와 차트 맥락을 복기한다. 다른 종목/다른 회차 기록을 임의로 섞지 않는다.
- 이미 끝난 매매의 판단을 교육 목적으로 돌아본다. 미래 매수·매도 가격/시점 지시를 제공하지 않는다. 서버 출력 안전 검사도 유지한다.
- AI 전송 동의와 계정별 저장 opt-in은 별개다. 기본 저장 비활성 흐름과 사용자가 명시적으로 켠 저장 흐름을 보존한다.
- 계정 전환·로그아웃 시 다른 사용자의 입력·복기·권한이 남지 않게 한다. 저장하지 않은 입력은 복구 가능하다고 약속하지 않는다.
- 사용자는 자신의 저장 데이터에만 접근한다. 저장을 끄는 동작과 기존 기록을 삭제하는 동작을 같은 것으로 설명하지 않는다.

## 이용권·광고·구독

서버가 인증·검증한 권한이 기준이다. 클라이언트의 광고 완료 표시나 결제 성공 화면만으로 이용권을 지급하지 않는다.

가입 보너스, 일간 무료·광고 추가 제공, 월간 무료 상한, 주간 심화 보상은 서로 다른 지급·사용량 정책이다. 주간 심화 보상은 별도 광고 목적과 진행도로 관리한다. 정확한 수치·상한·초기화 시각은 access_control.py의 FREE_* 상수, 환경 해석과 날짜/주기 계산을 확인하며 변경 시 관련 테스트와 본 문서를 함께 대조한다.

Pro는 실제 결제 주기에 따라 제공량을 계산하고 남은 주기 제공량은 이월하지 않는다. 별도로 구매한 소모성 복기권은 분리해서 보관하며 만료 없이 이월하는 의도를 유지한다. Pro 제공량과 구매 잔액의 차감 순서를 임의로 바꾸지 않는다.

Pro 사용자는 보상형이 아닌 광고를 보지 않는 정책이다. 보상형 광고는 무료 사용자의 추가 복기 경로이며 일반 복기 목적과 심화 보상 목적을 혼동하지 않는다.

상품 ID·수량·가격·base plan/offer는 access_control.py의 PRODUCTS/SUBSCRIPTIONS 및 [billingPolicy.js](../frontend/src/mobile/billingPolicy.js)가 구현 근거다. 과거 정책의 출시 할인 의도와 실제 Console 제공 여부는 분리한다. 상품 식별자를 바꾸거나 출시일을 추정해서 이벤트를 활성화하지 않는다.

## 계정·구매 실패와 복구

- 공급자 사용자 ID를 내부 계정에 연결한다. 서로 다른 공급자 계정을 이메일이 같다는 이유만으로 합치지 않는다.
- 구매 유형에 따라 package·product·status·order 등의 증거를 서버에서 검증하고 consume/acknowledge 책임을 유지한다. 이미 다른 내부 계정에 연결된 purchase token을 새 계정의 신규 지급에 재사용하지 못하게 한다.
- Google Play 구매자 식별자와 현재 StockBoda 세션 사용자를 직접 결합·대조하는지는 **Unverified/Open**이다. 현재 구현을 구매자 신원과 앱 계정의 직접적인 소유자 확인으로 설명하지 않는다.
- AI 실패 시 환급 처리와 같은 주문에서의 복원 규칙을 보존한다. 재시작 후 일관성은 아직 해결되지 않은 H7이다.
- export는 “전체 백업”으로 광고하지 않는다. 현재 코드의 내보내기 상한과 앱에서의 저장/공유 방식은 [DATA](DATA.md)와 [TESTING](TESTING.md)을 확인한다.
- 계정 삭제 이후의 구독·분쟁 기록·외부 알림 처리를 임의로 결정하지 않는다.

## 결정이 필요한 영역

공개 출시일과 Play 할인 설정, 삭제 후 최소 결제 기록 보관·외부 알림 처리, 전체 export 계약은 repository만으로 운영 의도를 확정할 수 없다. 사용자 승인 또는 외부 확인이 필요한 사항으로 계획에 기록한다.

오래된 [수익화 정책](ai_review_monetization_plan.md)의 모델명과 준비 상태는 현재 구현 근거가 아니다. 모델·토큰·제한 수치를 여러 문서에 복제하지 말고 코드와 검증기를 확인한다.
