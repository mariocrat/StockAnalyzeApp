# AI 복기 수익화 정책

## 이름 기준

구독, 분석 깊이, 소모성 이용권이 헷갈리지 않도록 사용자에게 보이는 이름을 분리한다.

- Pro: 월 구독 상품.
- 일반 복기: 단건 매매를 짧게 분석하는 AI 복기. 내부 타입은 `basic`.
- 심화 복기: 이번 매매와 최근 매매를 비교하는 깊은 AI 복기. 내부 타입은 `advanced`.
- 복기권: 구독하지 않아도 필요한 만큼 구매해서 쓰는 소모성 이용권.

UI 라벨은 아래처럼 사용한다.

- 일반 복기
- 심화 복기
- 일반 복기권
- 심화 복기 이용권

## AI 복기 종류

### 일반 복기

- 기본 모델: `gpt-5.4-mini`.
- 범위: 사용자가 선택한 단건 매매 1건.
- 출력: 한 줄 총평, 잘한 점, 아쉬운 점, 다음 체크리스트 3개.

### 심화 복기

- 기본 모델: 단일 매매 심화 복기에 맞춘 `gpt-5.6-luna`.
- `OPENAI_ADVANCED_REVIEW_MODEL` 설정으로 나중에 모델을 쉽게 바꿀 수 있게 둔다.
- 범위: 사용자가 명시적으로 선택한 단일 매매 묶음과 해당 차트 맥락. 다른 종목이나 다른 회차의 매매는 섞지 않는다.
- 분석 초점: 결과와 당시 판단의 품질 분리, 진입 가설, 위험 관리, 매수·매도 대응, 다음 복기 질문.
- 사용자에게는 모델명이나 별도 상위 등급을 노출하지 않고 `심화 복기` 한 종류만 제공한다.

### 투자 권유 방지 원칙

- 일반 복기와 심화 복기는 이미 끝난 매매를 교육 목적으로 돌아보는 기능이다.
- 실제 과거 체결 가격과 시각은 사실 설명에 사용할 수 있다.
- 향후 특정 종목, 가격, 시각, 날짜 또는 조건에서 매수·매도하라는 지시는 절대 생성하지 않는다.
- 목표가, 추천 매수가, 추천 매도가, 구체적인 손절가처럼 사용자가 그대로 실행할 수 있는 가격 지시를 만들지 않는다.
- "다음에는 몇 원에 사라" 대신 "당시 어떤 근거를 확인했고 그 근거가 깨진 시점을 기록했는가"와 같은 복기 질문으로 바꾼다.
- 모델 지시문뿐 아니라 서버 출력 검사도 적용하며, 금지된 거래 지시가 감지되면 해당 AI 결과를 사용자에게 전달하지 않는다.

## 무료 정책

- 가입 보너스: 일반 복기 5회. 만료 없음.
- 하루 기본 제공: 일반 복기 1회.
- 보상형 광고 1회 시청 시 일반 복기 1회를 제공한다.
- 광고 일반 복기 최대 2회/일.
- 월 무료 일반 복기 최대 30회. 하루 기본 제공과 광고 제공 사용량을 합산한다.
- 일반 복기용 보상형 광고는 일반 복기의 일간·월간 한도에만 반영하며 심화 복기 보상 진척도에는 포함하지 않는다.
- 사용자가 `심화 복기권 받기`를 선택해 본 보상형 광고만 주간 심화 복기 보상 진척도에 반영한다.
- 심화 복기권용 보상형 광고 5회 시청 시 무료 심화 복기권 1장을 지급한다.
- 무료 심화 복기권은 주 1장만 지급하고 최대 1장만 보유한다. 사용한 뒤 같은 주에 광고를 더 봐도 다시 지급하지 않는다.
- 미사용 무료 심화 복기권과 주간 광고 진척도는 매주 월요일 00:00(KST)에 소멸하고 0부터 다시 시작한다.

보상형 광고 정책은 서버 설정으로 조정한다. 기본값은 광고 1회당 일반 복기 1회, 광고 5회당 주간 심화 복기 이용권 1장이다. `ALPHAMATE_ADS_PER_ADVANCED_TICKET`으로 심화 복기 이용권 지급 기준을 바꿀 수 있다. `ALPHAMATE_FORCE_REWARDED_AD_CHAIN` 플래그도 있지만 기본값은 `false`다. 여러 광고를 연속으로 강제 시청시키는 흐름은 사용자 피로도가 높기 때문이다.

## Pro 정책

- 출시 이벤트 가격: 월 5,900원.
- 정상 가격: 월 7,900원.
- 월 제공량: 일반 복기 35회, 심화 복기 15회.
- Pro 사용자는 앱 전체에서 보상형이 아닌 광고를 보지 않는다.
- 보상형 광고는 무료 사용자가 추가 복기 접근권을 얻는 경로로만 유지한다.

## 1회성 복기권 상품

복기권은 구독이 아니라 소모성 1회성 구매 상품이다.

| 상품 ID | 사용자 표시 이름 | 수량 | 가격 |
| --- | --- | ---: | ---: |
| `basic_review_30` | 일반 복기권 30회 | 30 | 2,900원 |
| `basic_review_50` | 일반 복기권 50회 | 50 | 4,500원 |
| `advanced_review_5` | 심화 복기 이용권 5회 | 5 | 3,900원 |
| `advanced_review_10` | 심화 복기 이용권 10회 | 10 | 5,900원 |

상품 ID는 백엔드 상수로 분리하고, 실제 출시 전 Google Play Console 상품 ID에 맞춰 바꾼다.

## 이용 기간과 초기화

- 가입 보너스 일반 복기: 만료 없음.
- 첫 로그인 체험 심화 복기: 만료 없음.
- 구매 이용권: 만료 없음.
- 무료 일간 제공량과 광고 일반 복기 횟수: 매일 00:00(KST) 초기화.
- 무료 월간 일반 복기 한도: 매월 1일 00:00(KST) 초기화.
- 광고 보상 무료 심화 복기권과 광고 진척도: 매주 월요일 00:00(KST) 소멸 및 초기화.
- Pro 월 제공량: 현재 구독 결제 주기의 다음 갱신 시점에 초기화.

앱의 이용권 화면에는 서버가 계산한 다음 일간, 주간, 월간 초기화 시각을 한국 시간으로 표시한다.

## 차감 우선순위

일반 복기:

1. 무료 가입/일간 제공량.
2. Pro 월 일반 복기 제공량.
3. 구매한 일반 복기권.
4. 광고 시청 후 추가 제공량.
5. 구매 유도.

심화 복기:

1. Pro 월 심화 복기 제공량.
2. 광고 5회 시청 보상으로 받은 주간 심화 복기 이용권.
3. 구매한 심화 복기 이용권.
4. 구매 유도.

일반 복기 이용권과 심화 복기 이용권은 별도로 관리한다. 심화 복기 이용권으로 일반 복기를 사용할 수 있게 할지는 `ALPHAMATE_ALLOW_ADVANCED_TICKET_FOR_BASIC` 설정으로 분리하되, 기본값은 불가능으로 둔다.

## 카카오/네이버 로그인과 저장

카카오와 네이버 간편 로그인은 사용자를 식별하는 수단이다. 두 서비스가 AlphaMate 복기권이나 구독 상태를 관리해 주지는 않는다. 서버는 로그인 제공자의 토큰을 검증하고 `(provider, provider_user_id)`를 내부 사용자 ID에 연결한 뒤, 구독 상태, 복기권 잔여 수량, 광고 보상, 사용량 카운터를 AlphaMate DB에 저장해야 한다.

같은 사용자가 나중에 카카오와 네이버를 모두 연결하려면 앱에서 명시적으로 계정 연결 확인을 받아야 한다. 이메일이나 전화번호만 보고 자동 병합하면 제공자별 인증 정보가 달라 계정 충돌이 생길 수 있다.

매매 이력 저장은 사용자의 동의를 전제로 한다. 기본은 1회성 분석을 하고 지우는 개인정보 최소화 모드로 둘 수 있고, 나중에 "내 매매 복기 저장" 설정을 켜면 사용자별 매매와 AI 복기 이력을 저장한다. 이 경우 내보내기, 삭제, 보관 기간 안내가 함께 필요하다.

## 운영 전 교체 지점

- `dev-token`은 카카오/네이버 또는 OIDC 토큰 검증으로 교체한다.
- `dev-ad-reward`는 AdMob 보상형 광고 서버 검증으로 교체한다. 백엔드 SSV 저장과 차감 흐름은 구현되어 있다.
- 모바일 AdMob SDK는 보상형, 전면, 배너 광고가 연결되어 있다. 운영 배포 전 실제 AdMob 앱 ID/광고 단위 ID와 SSV 콜백 설정이 필요하다.
- `dev-pro-entitlement`와 개발용 구매 엔드포인트는 Google Play Billing 서버 검증으로 교체한다.
- 메모리 기반 지갑은 운영 DB 또는 Redis 기반 사용량 저장소로 교체한다.
- OpenAI API Key는 서버 환경변수 또는 클라우드 Secret Manager에만 둔다.
